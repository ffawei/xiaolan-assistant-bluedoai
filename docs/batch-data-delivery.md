# 用小蓝助手做批量数据处理：交付脚本前，先约定输入与验收

一批CSV文件需要合并，字段名并不完全一致，有的文件使用不同单位。这样的任务可以让执行型AI编写脚本，但验收应当从输入约定开始。

下面是一份方法示例，不是客户实测报告。

先建独立工作目录：input保留原始数据，output保存结果，scripts保存程序，logs保存运行记录。规定脚本只读input，避免把一次格式处理变成原始数据覆盖。

给小蓝助手的要求可以具体到这些内容：列出所有输入文件与字段；按提供的映射表统一列名；缺失值保留为空；单位换算只使用确认过的规则；相同主键出现多次时输出重复清单，不直接删除。

先用少量样例跑一轮。样例里应当包含正常记录、缺失字段、重复主键，以及一条单位不同的记录。每类样例的预期处理方式由任务负责人确定，不能只让生成脚本的模型再给自己打分。

检查输出时，可以比较输入与输出行数，核对每个原始文件是否被处理，抽查数值换算。程序不支持某种格式时，应当给出明确错误和文件位置，不能跳过以后仍写成全部成功。

结果目录还需要一份运行说明，写清依赖、启动方式和处理规则。交付脚本和日志，才方便下次数据更新时复用，也方便其他人接手检查。

小蓝助手 Blue（BlueDoAI）可以在授权范围内编写和运行复杂脚本，结合文件与支持的应用接续执行任务。这个流程适用于研发记录整理、跨应用资料汇总等需要批量处理的工作。涉及专业判断的结果，仍由负责人员审核。
