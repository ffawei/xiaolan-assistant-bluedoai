# AI把文件做出来了，交给同事前还差哪一步？

![小蓝助手任务示意，AI生成](../assets/articles/file-delivery-checklist.jpg)

一个文件夹里有汇总表、脚本、几张图片，AI也说任务完成了。接手的同事打开目录，却不知道该看哪一版，也不知道哪些数据没处理成功。

这种交接问题，靠再写一段漂亮的总结解决不了。要让下一位同事接得住，交付目录里得留下可以核对的东西。

下面以一项模拟的研发资料整理任务为例：将表格与图片按批次归档，生成汇总表，保留处理脚本。它说明的是交付方法，不对应某家客户的实际项目。

## 先让目录说明自己

开始前约定输出结构：原始资料放在只读目录，生成结果放在output，脚本放在scripts，处理日志放在logs。交付说明放在目录顶层。

说明不必长，但要能回答几个实际问题：从哪里开始看，怎样重跑，哪些文件未处理，哪些规则还需要负责人确认。

例如，一份表因为缺少批次号没有加入汇总，就应写明文件位置和缺失字段。不能把它和真正没有记录的空表混为一谈。

## 给文件做一份清单

清单至少包含相对路径、文件大小和SHA-256。它可以帮助检查拷贝后的文件有没有变化，也便于区分名字相同、内容不同的版本。

这里有一个容易误用的地方：哈希相同，只能说明所比较的文件内容一致。计算公式写错了，两份错误表格的哈希照样可以相同。内容是否正确，仍要抽查来源和业务规则。

目录里有上百个文件时，可以让小蓝助手编写脚本生成清单。要求清单写到被检查目录之外，避免把清单自己算进去；文件正在写入时先停下来，等成果稳定后再生成。

## 用一次小改动检查清单是否有用

复制一份交付目录作为练习样本，保留原目录。在副本里修改一个文本文件，再重新生成清单。

预期结果很明确：改动文件的SHA-256应变化；未修改的普通文件应保持一致。再测试删除一个文件、增加一个同名但不同目录的文件，检查对比结果能否分别指出缺失和新增路径。

这些练习只验证清单与比对流程，不代表表格内容已经验收。对研发数据，还要抽查批次、单位、原始记录与汇总结果的对应关系。

## 让小蓝完成任务时，把交接也写进去

可以这样给小蓝助手 Blue（BlueDoAI）安排工作：

> 读取我指定的研发资料目录，保留原文件。按已确认的批次规则整理表格与图片，输出汇总、来源索引和异常清单。先做一小批供我检查。确认后处理全部资料，将脚本、运行说明、未完成项和文件清单一起交付。清单写到交付目录之外，不覆盖已有文件。

负责人检查第一批时，重点看能否从汇总回到原始文件。之后再扩大处理量，才知道后面复制的是哪一套规则。
