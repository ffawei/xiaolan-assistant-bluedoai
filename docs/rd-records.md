# 研发记录分散在几张表里，小蓝助手怎样把资料接起来？

同一个试验项目，参数写在表格里，现场照片留在另一个目录，临时调整记在说明文档中。到复盘时，团队首先要回答的往往是：这张照片、这组数字，究竟对应哪一次试验？

让AI参与研发，适合先从这类资料关系入手。下面是一组模拟场景，用来说明任务安排，不是客户实测报告，也不涉及工艺效果承诺。

先把批次、版本和时间对应好

假设有A、B两个批次，每个批次都有记录表和图片。负责人先提供批次定义、文件范围和已确认的版本关系。资料里没有写出的对应关系，暂时留空并列入问题清单。

小蓝助手 Blue（BlueDoAI）可以在授权范围内整理指定目录，生成资料索引，把每条记录的来源文件、工作表或页码一起留下。遇到扫描件识别不清楚的数字，保留原图位置，方便人工复核。

先对齐规则，再合并数据

两张表都写“压力”，不代表单位相同；两列都叫“编号”，也未必指同一个对象。把字段定义和单位换算规则确认以后，再让助手编写脚本执行合并。

缺失值不要自动补成零，异常值也不要为了让表格整齐就删掉。可以同时交付汇总表和异常清单，让负责人检查哪些是录入问题、哪些是需要解释的真实现象。

比较版本时，保留变化的上下文

一份说明调整了参数，另一份记录改变了操作顺序。差异清单应当写明原内容、新内容和位置，必要时附上相关段落，方便工程人员判断变化的意义。

整理工具能够帮助找到变化，但不能仅凭文字差异判断工艺一定更好。涉及设备、安全、性能和实际工艺参数的决定，仍由负责的专业人员审核。

先跑一个小批次

从一份记录表、几张照片和一份说明开始。检查字段有没有漏、来源能不能打开、数值和单位是否对应。确认这一轮适用，再扩大范围。

需要脚本的任务，交付时把脚本和依赖说明一起留下。需要跨应用操作的任务，则写清软件版本、登录条件和可操作范围。复盘失败项，通常比只看“完成”提示更容易发现下一轮需要改进的地方。

研发资料整理的完成标准

接手人员能够顺着索引找到原始记录，能够看懂差异和未确认项，也能知道脚本做了哪些处理。源文件保持完整，涉及专业判断的部分留有审核位置。
